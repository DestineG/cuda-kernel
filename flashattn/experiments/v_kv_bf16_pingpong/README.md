# V / KV BF16 consumer ping-pong experiment

Six standalone CUDA sources: V-double and KV-double, each with single consumer, two consumers with no turn protocol, and two consumers with QK-ready ping-pong handoff. All variants use BF16 output and FP32 accumulators. The source repository and previous experiment directories are untouched.

Br is the number of Q rows per consumer WG. Dual variants have CTA rows=2*Br, 384 threads, one 128-thread producer and two 128-thread consumers. Consumers share K/V but own separate Q/O regions and independent registers. Ready barriers are shared; free barriers expect all 256 consumer arrivals after their WGMMA reads complete. One producer loads the union of the causal KV ranges. Both consumers iterate that same union, preserving per-row causal masks; an inactive tail consumer participates in ring and turn synchronization and writes no output. This simple implementation can do excess masked work in causal mode.

BF16 O aliases each consumer's own Q region. After all outstanding K generations drain, the producer releases the epilogue; each consumer finishes its own final PV, writes its disjoint full-tile shared output or partial global output, then acknowledges. Producer TMA-stores only complete consumer tiles after both acknowledgements. No Q region is overwritten while it can be read by another WG.

The ping-pong protocol has two reusable turn barriers seeded to WG0. A WG takes its turn before QK, and hands off when QK results are ready, just before masking/max/exp/sum. During steady state that WG's preceding PV may still be in flight. Final PV takes one last turn. This is an experimental QK-ready schedule derived from our existing overlapped kernel, not a verbatim implementation of NVIDIA/Dao-AILab FA3. The plain dual-consumer version isolates scheduling from consumer-count changes.

Run from flashattn: `python tests/run.py all --config tests/configs/full.json --run-root ../runs --name v-kv-bf16-pingpong`. Resume/report/archive use `--run <path>`.

All six kernels are independently tuned with six per-WG tile shapes, redistribution off/on, producer targets 32/40/48/64 and consumer targets 128/160/192/224/232/240/256. Targets exceeding the CTA launch pool are excluded and recorded: single consumer <=65536; dual consumers <=64512 (384 threads x 168 registers). The failed initial pool-size assumption and diagnostic log remain in the stopped first run. Joint search covers promising tiles/register pairs/TMA boxes; this is staged search, not full Cartesian search. Twelve default configurations undergo 157 CPU correctness inputs and four sanitizer gates before search. Selected configs repeat all CPU checks and gates. Numerical failures stop work. The 268-case fresh performance matrix includes official FA3 (num_splits=0), private ATen varlen, and public per-sequence forced Flash SDPA. Twelve representative inputs repeat in reversed order. Five CUDA-graph rounds; launcher wall time is separate.

Report layout: input / kernel and hyperparameters / measured results. Br and CTA rows are both available. No speedups or relative values. Sources, source diffs, original source hashes, build logs, exact FA3 package, configurations, raw results, failures/exclusions and reproduction commands are archived. Large rebuildable binaries/reference caches/toolchain are excluded.
