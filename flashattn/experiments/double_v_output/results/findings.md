# double_V BF16 输出独立实验

BF16 写回能降低部分场景耗时，但本次数据不支持将与官方 FA3 的长序列性能差距归因于 FP32 写回。小幅变化应结合五轮范围和重复确认一起看。

只修改 H800 独立目录中的副本，四号机仓库与原始测试产物未改。FP32 累加、QK/PV/softmax 和同步协议保持不变。完整 tile 改为 packed BF16 shared store + BF16 TMA；尾 tile 改为 packed BF16 global store。输出 box 宽度从 32 个 FP32 元素改为 64 个 BF16 元素，保持 128B swizzle。

输出 shared memory 复用 Q/K/V 区域，因此相同参数下总动态 shared memory 不变。下表两种输出均使用 Br=Bc=64、关闭寄存器重分配。B=1，Hq=Hkv=16，D=128，causal=true，Q=KV。单位 μs，为五轮 CUDA graph 的中位数；这不是端到端时间。

| Q=KV | double_V FP32 | double_V BF16 | 官方 FA3 | PyTorch ATen varlen |
|---:|---:|---:|---:|---:|
| 128 | 10.109 | 9.507 | 11.495 | 10.218 |
| 2048 | 126.385 | 120.141 | 53.679 | 142.821 |
| 8192 | 1417.848 | 1402.316 | 603.128 | 1454.304 |

2048 序列的反序重复确认：FP32 126.336 μs，BF16 120.381 μs，官方 FA3 53.729 μs。该场景的 BF16 改动在重复确认中仍有收益；官方的性能差距仍然存在。8192 序列两种输出的五轮时间范围重叠，不能仅凭中位数的小差异认定稳定收益。

验证：157 组正确性输入；默认及最终配置四种 sanitizer 全部通过。312 次有效舍入对照全部相等。零 KV 无写回单列，不算 attention 正确性。268 组性能输入、12 组反序确认，共 2014 条性能记录；108 个编译配置，tile 搜索 288 条、寄存器搜索 672 条、组合搜索 600 条，全部通过。无失败、淘汰或不支持记录。FP32/BF16 各自独立调参；不是全笛卡尔积穷举。
